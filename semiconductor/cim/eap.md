# CIM 业务篇

# 0.CIM

EES 为设备自动化与控制板块的统称，含 EAP, FDC, RMS, RCM, APC 五个子系统. EAP 是该域的通信与执行底座，承担设备接入、指令下发、数据采集与解析；FDC, RMS, RCM, APC 均以 EAP 采集与下发的数据为输入，不各自直连机台.

# 1.EAP

## Tool ID Naming rule

- **数据源**：《芯源机台命名规则\_V1.1》（平台建设中心 IE，2026-09）第 2~7 页；`Tool ID naming rule.xlsx`「Naming Rule database」表，内含平台码 A1:D8、位置码 A12:D16, Module 码 A20:D72, Process 码 H1:M547、厂商码 O1:U1 五张码表.

### 建立规则的动因与目标

- **现状问题**：主数据采用中文名称，对本部门易于掌握，但对标业务成熟公司存在五类问题：跨部门沟通协作难、半导体工艺词汇多为舶来品导致多种设备混淆、中文难以链接 MES 等系统、业务扩展受阻、难于进行资产管理.
- **业界做法**：国内成熟工厂的设备命名采用大写字母加数字的 7~8 位. 字母位承载厂别、工艺模组、厂商、制程等核心业务信息，数字位表示该设备群组采买的第几台.
- **目标**：易管理、易沟通、成体系、后续可延展.

### 与业界大厂的可比性差异

| 对比项               | 业界成熟工厂                   | 芯源                                   |
| -------------------- | ------------------------------ | -------------------------------------- |
| 业务种类             | 少                             | 多                                     |
| 业务范围             | 单一的晶圆制造／封测／基板制造 | 涵盖晶圆制造／封测／基板制造／衬底制造 |
| 机台数               | 多                             | 少                                     |
| 企业性质             | 量产                           | 研发                                   |
| 主设备是否在同一楼层 | 是                             | 否                                     |
| 晶圆制造种类         | 一种或两种                     | 4 种以上                               |

- 机台数少而业务种类多，数字位的规模优势不存在，字母位须承载更高的信息密度.
- 主设备跨楼层，位置信息无法隐含在工艺模组内，须单列码位.

### Process 码表

- **规模**：表头外 546 行，覆盖 5 平台 7 子平台，全部行均已赋码. 行数分布为化合物 120、封装-A 96、热管理材料／表征 92、测试 86, CCC 85、封装-B 53、外延 14.
- **唯一码**：478 个，其中 477 个为 3 位字母，1 个为 2 位（`1B`）.
- **取码方式未统一**：工艺侧多取 Process 英文名的括注缩写或业界通用缩写，如 HTC 对应 High Temperature CVD, TDS 对应 TSV/Damascene Sputter, LTC 对应 Low Temperature CVD, WUF 对应 Wafer-level Underfill；测试侧多取设备缩写，如 TMP, LTS, HDL, PRM, HLT, JSD. 两类混编于同一码表.
- **一码多义**：55 个码被复用，涉及 68 行，占 546 行的 12.5%. 典型冲突如下.
- `CDM` 三义：化合物／光刻的 CD SEM、测试／ESD 的 CDM（器件放电模型）、CCC／量测的 critical size measurement.
- `TEM` 两义：测试／多物理场失效性分析的透射电镜、CCC／薄膜的 thermal evaporation medium.
- `TDT` 两义：测试的 TDTR, CCC 的 two-dimensional materials transfer.
- `WCP` 两义：化合物／预处理的 Wafer clean for InP、化合物／芯粒互联的 Wafer CMP.
- `AOI` 三义，分属封装-A／Metrology、封装-B／Litho、化合物／在线检测.
- `SGM` 四行内容相同，同属封装-B／Mechanical.
- **完全重复行**：2 组，为化合物／芯粒互联的 `WCP`（晶圆抛光机）与 `LAP`（研磨机），各重复登记一行.
- **Module 列与码表不一致**：`Plating` 与 `plating`、`Surface treatment` 与 `surface treatment` 属大小写分裂；`CMP`、`扩散` 与空值三项未登记入 Module 码表；码表中的 `热处理`、`研磨` 在 Process 表无对应行.
- **外延子平台的空 Module 行**：两行 Module 为空、Process 码同为 `1B`，一码对应氮气柜与氦检仪两类设备，且该码为 2 位，与 3 位码规定不符.

### 附属设备命名规则

- **编码格式**：`主设备ID-类型码-序号`，类型码 1 位字母，序号 2 位数字、不足补零. 示例 `ATLTCT11-P01` 即 ATLTCT11 主设备的第 1 台真空泵，同类型第 2 台为 P-02，序号按类型分别累计.
- **沿用理由**：与行业主流做法同源，结构稳定、从属关系清晰.

**五大命名原则**

- 唯一性：全局唯一，同类工具以主设备编号区分.
- 继承主设备编号：主设备 ID 直接作前缀，不另起编号.
- 类型码统一：以预定义对照表约束，全项目同一套缩写.
- 序号固定位数：固定两位，不足补零.
- 避免混淆字符：不使用字母 O, I，避免与 0, 1 混淆.

### 1. 为什么先下 PJ 后下 CJ

## 协议与标准

### SECS/GEM 协议栈怎么分层

- SECS-II(E5) 定义消息语法，其上 GEM(E30) 定义设备行为规则，其下 E4 承载串口、E37 承载 HSMS over TCP.
- GEM300 = E39 + E40 + E87 + E90 + E94（E109 为光刻专用），E39 是语法底座，应先读.
- HSMS 消息头 10 字节，Session ID 常用 0xFFFF；定时器典型值 T3=45 s（回复超时）、T5=10 s, T6=5 s, T7=10 s, T8=5 s，实际以机台手册为准.
- E30 含三套状态机：通信状态、控制状态、处理状态.
- EDA 三代 Freeze：Freeze1（1105，SOAP 1.1）、Freeze2（0710，SOAP 1.2，当前主流）、Freeze3（HTTP2 + gRPC + protobuf，开发中）. Freeze1 与 Freeze2 不互通，采购技术要求应写 Freeze 版本号，而非单列标准号.
- 标准现行版本：E30-0725（2025-07）、E5-0622, E37-0222.
- 中文社区资料（CSDN 等）错误率高，实现细节以 E5 原文与机台手册为准.

@see: `cim.md` → `# EAP` → `## EAP Terminology`

### Recipe 消息 S7F3 与 S7F23 怎么区分

- S7F3 为非格式化配方发送（Process Program Send），报文格式 `<L[2] <A PPID> <B PPBODY>>`，PPBODY 为设备专有的二进制数据块，由 S7F4 应答；S7F23 为格式化配方发送（Formatted Process Program Send），主体是结构化的参数列表，由 S7F24 应答.
- 选择依据是机台是否声明支持格式化配方：声明 GEM300 且手册列出 S7F23 的机台可走参数级通道，能做参数级比对；仅声明 S7F3 的机台只能做文件级管理，即按 PPID 加内容比对，与吾拾微电子三台的口径一致.

### E87 载具状态机与事件编号怎么对应

- E87 载具状态机七态：0 NOT_INSTANTIATED（装载口无载具）、1 ID_NOT_READ, 2 ID_VERIFICATION_OK, 3 ID_VERIFICATION_FAILED, 4 NOT_ACCESSED, 5 IN_ACCESS, 6 CARRIER_COMPLETE.
- 事件编号与状态迁移成对：E87_06 Carrier Arrived 对应 0→1，承载消息为 S6F11 CarrierArrived；E87_03 Carrier ID Read 对应 1→2，承载消息为 S6F11 Carrier ID Report（不是 S3F27）；E90_11, E90_12 为基板映射相关事件.
- 编号与消息不在同一层：E87_06, E87_03 是标准内的事件序号，S6F11, S3F17 是承载消息，画时序图时须分行标注，不可相互替代.

### PJ 与 CJ 分别归属哪条 SEMI 标准

- PJ（Process Job）对应 SEMI E40 工艺作业管理，消息为 S16F15（PRJobMultiCreate）创建、S16F16 应答；CJ（Control Job）对应 SEMI E94 控制作业管理，消息为 S14F9（Create Object Request）创建、S14F10 应答.
- 分层职责：PJ 定义 "做什么"，包含加工哪些晶圆的哪些槽位与用哪个 Recipe；CJ 定义 "怎么做"，编排一个或多个 PJ 的执行顺序、资源与优先级.
- 先 PJ 后 CJ 的成因在 CJ 的创建前提：创建 CJ 时须指定其管理的 PJ，PJ 不存在则 CJ 无管理对象，创建不成立.

@see: 本文件 → 「为什么先下 PJ 后下 CJ」（该条讲业务顺序，本条讲标准归属与报文）

### 采数链路为什么是 S2F33 到 S6F11 四步

- 标准链路：S2F33 定义报告 → S2F35 绑定事件与报告 → S2F37 订阅 → S6F11 上报. 前三步是订阅机制，第四步是运行期上报.
- 该机制可自建替代，但替代后即脱离统一事件平台，FDC/SPC 数据链路无法直接复用.

### GEM 控制状态三态是什么，主机权限边界在哪

- 三态为 Offline, Online Local, Online Remote. 主机可将设备从 Offline 拉至 Online，但落在 Local 还是 Remote 由设备端本地 / 远程开关（操作员）决定，主机不能强制夺取；开关拨动后设备须主动上报控制状态变化事件.
- 报文：S1F15/S1F16 请求离线与应答（OFLAACK 0=OK, 1=Refused）；S1F17/S1F18 请求在线与应答（ONLACK 0=OK, 1=Refused, 2=Already ON-LINE）.
- 三态通常另设状态变量承载，常见取值 1= 离线、4= 在线本地、5= 在线远程，并挂在状态变化事件中.
- 性质区分：S2F33/35/37 属事件订阅机制，可自建替代；控制状态三态属控制权归属，是 EAP 下发命令的前提，**无替代方案，必须实现**.

依据：2026-09-14 量测机台 SECS/GEM 手册评审；该手册 S10F1 仅判断 "控制状态为 OnLine" 即执行，不区分 Local/Remote，等于允许主机在操作员本地模式下启动测量.

### 量测机台手册实例暴露了哪些规范问题

- 对象文档 `D:\EAP机台LIST\SECSGEM设备端通信方案及伪代码说明草稿.docx`（27 KB，7 节）.
- 实现范围：SECS-II over HSMS（设备作被动端，默认端口 5000），**不含 GEM 设备模型**，无状态模型、无 Collection Event/Variable、无事件报告订阅.
- 数据通道为自定义 Stream 10 主动上报 + 标准 S5F1 报警：S10F1/F2 开始测量命令与确认、S10F3/F4 停止测量命令与确认、S10F9 测量结果主动上报（WaitBit=false）、S10F7/F8 请求设备状态与状态数据、S5F1 报警（B[1] ALCD, U1 ALID, A ALTX）.
- 测量结果数据结构：管流 (mA)、管压 (kV)、曲线名称（20 字节定长）、元素列表 L[名称, 值, 单位]（XRF 特征）.
- HandleMessage 仅覆盖 (1,1)(1,13)(1,15)(1,17)(2,17)(5,3)(6,15)(10,1)(10,3)(10,7)，未知消息统一回 S9F5；全文无 S2F33/S2F35/S2F37 收发实现，也无 S6F11 主动上报逻辑.
- **规范错误**：`case (6,15)` 返回 S6F11 不符合 SEMI E5. S6F15（Event Report Request）应以 S6F16（Event Report Data）应答，S6F11 是设备主动发送的消息.
- **控制状态缺口**：只有 OffLine/OnLine 两态，无 Local/Remote 区分；状态变化无主动上报，主机只能靠 S10F7 询问，存在 "EAP 以为在线、实际操作员已接管" 的失控窗口；S10F2 应答仅 B[1] 0= 成功 /1= 失败，未区分 "因状态不允许而拒绝"；S1F16/S1F18 未定义拒绝码取值.
- 其他缺口（比 S2F33/35/37 更紧要）：ALID 清单与报警分类未定义；结果上报时序未定；无 PPID/ 工作曲线下发通道，若需 EAP 下发曲线应补 S7F1/S7F3/S7F5.
- 手册第 7 节待确认项：6000C 带多样品转盘，是否需传入样品腔编号 / 工作曲线 / 测量时间参数；多样品腔测量结果为汇总上报还是逐次上报.

### 量测机台手册是否必须补 S2F33/S2F35/S2F37

- 从 EAP 上线最小闭环看：**不强制要求补**，S10F9 + S5F1 + S10F8 已构成测量业务闭环.
- 从平台一致性看：若要求纳入统一事件平台、统一 FDC/SPC 数据链路或 GEM 合规，则 **必须补** S2F33+35+37 并配 S6F11.
- 结论取决于验收口径，属 "可补可不补"；与控制状态三态（必须明确项）性质不同.

### EDA Freeze 版本怎么选

- Freeze2（0710，SOAP 1.2）为当前主流选型；Freeze3 尚在开发中，不建议作为本期基线.
- 采购技术要求写 Freeze 版本号，不要只写标准号，否则不同 Freeze 的设备无法互通.

### SEDD(E172) 为什么值得写入采购要求

- E172 SEDD 是机台以标准格式自描述 SVID/EC/CEID/ALID 的数据字典文件，EAP 导入后可自动生成变量映射配置.
- 人工翻译手册录入数千个 VID 极易出错，SEDD 可替代该环节，是本次梳理中对 EAP 性价比最高的标准项.

### EAP 的复用单位是手册还是设备台数

- 复用单位是 **同一份手册文件**（手册指纹），不是同厂商同设备名，也不是设备台数.

### 复用与定制的边界怎么划

- V5.0 的 138 行实测分档：A 可复用（S7F19+S7F3 齐备）58 台 42.0%、B 仅列表（S7F19 only）23 台 16.7%、C 无配方消息 40 台 29.0%、X 非 SECS 资料 17 台 12.3%. 剔除示波器 / 频谱仪 / 矢网等 25 台仪器类后（113 台）为 51.3% / 20.4% / 28.3%.
- 外推至接入范围 461 台：可复用 ≈168 台、需定制 ≈124 台（仅列表 67 + 非标 57）、需厂商补做 ≈93 台、不涉及 ≈76 台（只读）.
- 驱动套数：可复用模块 ≈104 套、定制驱动 ≈50 套、待补册 ≈49 套、非标协议栈 45~55 套.
- 与 V4（47 台）对比：复用率稳定在 48%~51%，B 档下降 11 pp，C 档上升 8~13 pp.

### 2/4/6/8 吋非标机台手册必须提供哪些必要信息

- 通信与配置必备项：HSMS 通讯参数（IP、端口默认 5000, Active/Passive 连接模式、T3/T5/T6/T7 超时）、Device ID、受支持的 SECS-II 消息清单（Stream/Function 逐条列出）、GEM 合规声明（声明符合 SEMI E4/E5/E30/E37 及所实现的功能子集）.
- 设备模型必备项：设备状态模型图或状态转换表，含 Idle, Executing 等状态及转换条件；ECID 清单及其数据类型与取值范围，对应 S2F13/S2F14 查询、S2F15/S2F16 设置；SVID 清单及含义；CEID 清单与业务事件的对应关系；CEID 与 SVID 的关联，即哪些变量随哪个事件上报.
- 判定口径：上述各项缺失即无法开展对接开发，属 P0. 手册未声明而机台实际具备的能力，须在测机阶段以实测方式补证据，不能以 "未声明" 直接判定为不支持.

### 手册检查项怎么按信息获取时机分级

- 现行 P0/P1/P2 分级回答 "重要程度"，另有一条平行分法回答 "从何获取"：P0 必须从手册获取，缺失即阻塞开发；P1 手册须声明支持，具体取值与行为留到测机阶段验证；P2 属可选或按项目需求决定.
- 两条分法须并用：重要程度决定验收基线，获取时机决定倒排工期，即哪些项允许在测机窗口补、哪些项必须在 Move In 前锁死.

### 手册未声明 S16F15/S14F9 怎么判断机台支持

- 先查手册的 "支持标准" 或概述章节有无 SEMI E40（Process Job Management）与 SEMI E94（Control Job Management）声明，该声明是相关消息成立的前提.
- 再查 Stream 14（对象服务）与 Stream 16（工艺作业）章节是否列出对象模型与服务；即便未逐条列出 S16F15, S14F9，章节存在且定义了对象服务，即说明能力具备而文档不全.
- 最后在线验证：以 S1F3/S1F4 查询已定义的 SV，以 S14F1 类查询探明对象支持，实测证据优先于手册缺省.
- 判定口径：手册缺项不等于能力缺失，但缺项须转为 "待补册" 或 "实测确认" 项，不得直接按 "不支持" 计入定制开发量.

### 2/4/6/8 吋非标机台按 EAP 开发标准分几类

- 基础 GEM（GEM200/E30）：多为 2000 年前后设备，通信走 RS-232 上的 SECS-I，速率通常 9600 bps、半双工、无心跳，网络接入须先经串口转以太网；无标准 Job 概念，EAP 侧须用 S2F41 远程命令配合配方下发组合出虚拟任务状态机.
- 非标或无协议（Legacy）：无标准协议，走 RS-232/485, PLC 或自定义二进制协议，须逐台评估转接方案.
- 完整 GEM300：支持 E40/E87/E90/E94，可走标准作业流.
- 分档是复用与定制边界的上游判据，决定 EAP 开发工作量与报价口径.

@see: 本文件 → 「手册完备度怎么分档，P0 口径是什么」（五档看手册完备度，三类看机台能力）

### 从手册能否初判机台的全自动、半自动或只读

- 可以初判，判据六项：控制状态模型须支持 ON-LINE REMOTE，即声明 Remote 状态下 EAP 拥有设备控制权；远程命令 S2F41 的 RCMD 列表含 START 或 RUN 类命令且参数含 Lot ID 或 PPID；配方支持 S7F3 或 S7F23 下发；载具操作支持 S3F17（E87）；事件上报 S6F11 含工艺开始与结束类 CEID；批次识别能力，能经 S2F41 参数或 S7Fx 接收 Lot ID 与 Wafer ID.
- 六项全具备为全自动候选；缺 S2F41 或批次识别能力者降为半自动；仅能上报状态、不能下发控制者归只读.
- 该判据适用于已收到手册的机台批量化初判，人工复核仅处理判据相互冲突的个案.

@see: 本文件 → 「EAP 接入范围、New Type 与 Rollout 怎么估」

### 无 SECS 能力的非标设备用什么 PLC，怎么转成 SECS/GEM

- 常见 PLC 品牌与协议：三菱 Q/R/FX/iQ-R 系列走 MC 协议，西门子 S7-300/400/1200/1500 走 S7 协议，欧姆龙 CP/CJ/NX/NJ 系列走 FINS 协议，倍福 CX/BX 系列走 ADS 协议；跨厂商通用协议为 Modbus 与 OPC UA.
- 转 SECS/GEM 三条路径：专用协议转换网关（如 EIGEM-HMI, NxSphere GEMBridge、台达 DIASECS-GEM Box），以标签映射方式把 PLC 变量映射为 SVID/CEID/ALID，部分产品可直接生成 SECS/GEM 参考手册；软件库或 SDK 自研驱动；PLC 侧加装 SECS/GEM 功能模块.
- 选型口径：优先选支持 Modbus 或 OPC UA 的 PLC，可减少后续网关适配的定制量. 网关方案属 EAP 侧转接开发，须计入定制工作量.

@see: 本文件 → 「设备采购侧的接口要求」

### 采购阶段怎么用合同锁定 "验机必须上线 EAP"

- 技术协议须写明协议与标准范围：必须支持 SECS/GEM，接口符合 SEMI E30（GEM）、E37（HSMS）、E5（SECS-II）；需要 GEM300 能力的另注明 E40, E87, E90, E94.

### 机台厂商为什么会有代理厂商

- 三种动因：新厂商或新机型进入市场面临信任壁垒，代理商以行业信誉与客户关系提供背书；原厂自建全球本地服务团队成本高，代理商承担从选型、安装、调试到维护的本地服务；代理商模式属轻资产扩张，可分担备货与财务风险.
- 对本项目的意义：技术细节与协议规范的最终信息源是原厂，代理商多为执行与支持角色. 手册缺项、MDLN 与文件名口径不符一类问题应向原厂确认，不宜止步于代理商答复.

### 未声明 GEM300 的设备怎么下 Job

- 无 GEM300 状态机时改用 S2F41 远程命令触发任务：EAP 下发含 PPID 参数的远程命令，命令名称通常为 START 或 RUN，设备据此加载配方并执行；执行过程与结果经 S6F11 上报，报警经 S5F1 上报.
- 配方前置动作：执行前经 S7F3 或 S7F23 下载配方，下载后经 S7F19 查询设备端配方列表、经 S7F5 比对校验和确认一致.
- 须与厂商确认：是否支持 START 类远程命令、命令的准确名称与所需参数.
- EAP 侧须自建虚拟任务状态机：缺少标准化的 PJ/CJ 状态机，任务状态只能由 EAP 自行维护.

依据：本项目 MBE 等外延设备手册未声明 GEM300.

### 串口服务器与 SMIF 在接入上要注意什么

- MOXA 一类串口服务器用于把 RS-232/485 老设备接入以太网，属非标设备转接路径中的一种，转换器由 IT 自购；采用时须留意转换延迟与丢包对 SECS 时序的影响.
- SMIF 为标准机械接口，由三部分构成：封闭并运输晶圆盒的 pod、开合 pod 的装载端口（SMIF I/O）、以及与工艺设备整合的洁净室接口. 它规定了装载口与载具的物理形态，进而影响 EAP 侧的载具建模与 S3F17, S3F18 校验路径.

## 系统架构与功能

### EAP 分层架构与部署原则

- 五层结构（自上而下）：上位系统层（MES/RMS/APC/FDC/AMS/YMS/ 看板报表 / 泛微门户）→ 标准集成接口层（RESTful API, Web Service, Message MQ, DB Interface, TCP/IP Socket, File/FTP）→ 中间应用层（功能域）→ 工业通信协议层（SECS/GEM·HSMS, SECS-I/SECS-II, Modbus TCP/RTU, OPC-UA/DA, PLC/RS-485, Serial-TCP/UDP）→ 设备接入层（工艺制造、量测检测、封装划片、测试、环境监测、其他设备）.
- EAP Service 内部再分三层：连接层（CIM 适配、中间件、API 网关、协议转换、连接管理、会话管理）、业务层（跑货流程、状态机、机型配置、设备控制、Recipe、报警）、驱动层（SECS Driver, HSMS, GEM300, OPC UA, Modbus、封装）.
- 多平台 GUI 统一经 HTTPS 接入 Host Interface，终端含 PC Web, PC APP, PDA、手机、平板；接入办公 OA（泛微）门户 SSO 单点登录与门户跳转.
- 四大网络区域：办公网 VLAN10、应用服务区 DMZ VLAN20、管理与数据区 VLAN30、设备控制网 VLAN40. 中间件、管理平台与数据库集中划入管理与数据区.
- 部署原则：EAP Server 1:1 Tool，单 Server 跑约 30 进程，理由是 FAB-EQP 影响最小化而非资源最大化，Server 数量据此估算. 多尺寸混线时按区域 / 尺寸 / 协议类型分组部署，老设备 RS232+MOXA 与 12 寸 HSMS+EDA 不混在同一 Server.
- EQP 预留网口一般 8 个.

### EAP 与周边系统的集成边界怎么界定

- 已确认的集成范围：EAP 与 MES, RMS 集成，并新增与 APC 集成；与 AMHS, SPC 目前不集成.
- 与 MES：接收 MES 下发的批次、工单信息与生产指令，完成载具与晶圆身份校验、配方绑定与启用，回报设备状态、完工数量与异常事件.
- 与 RMS：按 MES 指定获取对应版本的工艺 Recipe，校验机台当前 Recipe 一致性，支持配方参数自动下载至设备.
- 与 APC：把设备实时工艺参数与量测数据上送 APC，接收 APC 计算的工艺补偿参数（如光刻机 Chuck 焦面补偿 Offset）并下发设备执行，同时接收工艺偏离预警以触发暂停或参数修正.
- 与 AMHS 的边界须书面化：搬运指令的发起由 MCS 侧承担，EAP 只承接设备上下料联动与物料到位、移出状态反馈.

- 工单下发不属 EAP 职责：工单（Work Order/Lot）的创建、拆分、派发与全流程管理由 MES 承担；EAP 处于执行层，被动接收 MES 下发的批次或工单信息，校验后用于控制设备执行并回报结果. 原稿 "实现工单下发" 须改为 "接收 MES 下发的批次与生产指令".
- "设备互联" 存在歧义：该词易被读作设备与设备之间的互联，实际含义是 EAP 分别与设备连接、与上位系统集成，标题应改为 "设备通信与系统集成".

### FixBuffer 场景的完整时序与事件链是什么

- 分八个阶段：载具到达（含 Load Port 预约校验）、载具 ID 读取、主机验证、载具门开启、晶圆映射、工艺任务下发、作业执行与事件上报、载具卸载.
- 关键消息：载具到达为设备上报 S6F11 CarrierArrived（E87_06）；EAP 向 MES 查询该 Load Port 有无预约并取回结果；ID 读取为 S6F11 Carrier ID Report（E87_03），此前版本误写为 S3F27；主机放行为 S3F17 PROCEED_WITH_CARRIER，设备回 S3F18；映射信息另有第二次 S3F17 校验，设备回 S3F18 后方可 Track In；Slot Map 经 S12F1 上报.
- 作业下发链：Track In 之后 EAP 依次下发 S16F15 创建 PJ 与 S14F9 创建 CJ，设备分别以 S16F16, S14F10 应答，S14F10 之后设备开始作业.
- 事件上报链：CJ start, PJ Queue, PJ Start, Wafer Start, Wafer Process Start, Wafer Process End, Wafer End, PJ End, CJ End，方向均为设备指向 EAP，且每个事件 EAP 均须对应转发至 MES.
- Track In 定在工艺执行前，即 PJ/CJ 下发完成、机台开始作业之前；Track Out 在工艺完成后. 两者均为 EAP 与 MES 之间的业务通知，不属 SECS 消息.
- 图件口径：参与方为 AMHS, Tool, EAP, MES 四泳道，任一事件须有明确的起止系统，已按此口径产出可编辑的 draw.io 版本.

### 操作日志与审计日志的区别是什么

- 操作日志面向技术故障定位，记录系统、进程与代码层面的异常（服务启动失败、数据库连接超时、内存溢出等），数据量大、格式杂，主要读者为开发与运维人员.
- 审计日志面向安全合规与事后追溯，记录 "谁、何时、从何 IP、对何对象、做何事、结果如何"，只追加不可删改，主要读者为审计人员与 IT 内控.
- EAP 侧审计日志至少覆盖三类：权限与账户变更（建用户、授予机台控制权、重置密码）、核心业务配置变更（Recipe 修改、设备参数调整、模型与规则变更）、关键控制动作（远程命令下发、报警处置）.
- 功能描述中两者并列出现时应分开表述，不以 "运维日志" 一词合并，否则合规要求无法落条.

### 运维相关功能的标题怎么改

- 原 "运维管理与系统管理" 过宽，未体现内容细分. 按内容拆为三块：运行监控（运行状态监控、远程查看设备连接状态、异常告警推送、系统自检）、系统管理（用户权限、配置备份与恢复、在线升级与回滚）、审计追溯（操作日志与审计日志）.
- 改动理由：审计追溯为独立合规功能点，并入 "运维" 会被淡化，须单列.

### EAP POC 要验证哪些问题

- POC 的宗旨是先与用户对齐系统能管控什么、不能管控什么，避免交付范围的预期偏差.
- 待验证清单：服务器代码意外丢失是否影响正在 run 货的机台；客户端 GUI 能否手动清理残帐并限定可访问网段；是否支持批量启停 EAP；机台同时挂 FDC 走什么机制（能自动 run 货的走 PT 转发，另有 Y-Gateway Channel 做 SECS 转 XML/JSON，或走虚拟 EAP）；管理平台上的预约操作如何执行；EAP 日志能否自定义保存周期（三个月、六个月），以及 Trace Log 具体指什么；是否支持在线发送单条指令、不停机发单；非标机台的开发分类标准、手册应包含的内容与 PLC 点位图（与 RCM 相关联）；是否支持热更新、无需启停进程；S7F3 与 S7F23 在何种情况下用于把 PPBODY 下发给设备（机台不允许存 Recipe 时，Recipe 多保留在机台本地）；是否支持开源一键式部署.
- 与既有条目的衔接：机台是否声明格式化配方见本文件「Recipe 消息 S7F3 与 S7F23 怎么区分」；非标机台分档见「2/4/6/8 吋非标机台按 EAP 开发标准分几类」.

## 网络与厂务条件

### 机台与 EAP 的通信网络怎么设计

- 按三层功能组织：机台接入层位于产线现场，接入生产机台、IT 边柜内设备与机台自带电脑；FAB 数据中心层位于核心机房，部署 EAP 与 MES 等生产系统；生产辅助网络层为 AGV、天车等移动设备提供无线覆盖.
- 机台与 EAP 之间经 TCP/IP 承载 SECS/GEM，通信中断恢复时间建议不超过 3 秒，该指标须写入网络设计基线.
- 冗余设计：核心交换机双机热备，机台接入侧避免单点链路.
- 与既有部署原则的关系：四大网络区域（办公网 VLAN10、应用服务区 DMZ VLAN20、管理与数据区 VLAN30、设备控制网 VLAN40）是区域划分，三层功能是接入视角，两者并行使用.

## 立项与建设依据

### 为什么要建 EAP 与 FDC

- EAP 必要性六点：设备异构接入、Recipe 全生命周期管理、过程数据采集与追溯、作业防错、少人化连续运行、OEE 度量基础.
- FDC 必要性六点：工艺窗口严苛性、事后检验转过程实时管控、故障检测与分类、数据资产与工艺知识沉淀、设备健康管理、良率分析根因追溯.
- 二者构成闭环：EAP 负责数据采集，FDC 负责数据判读.
- 平台定位不同于量产 Fab：本中心核心产出是 "可复现、可交付的工艺能力"，对数据可追溯性与工艺可复现性的要求高于量产线；多品种小批量、换线频繁导致人工防错不可靠.

### CIM 为什么必须与机台 move in 同期展开

- CIM 与设备存在三重耦合：前向耦合（GEM 合规、接口契约、采集计划须先于设备到位）、后向耦合（验收数据、工艺基线、数据资产须自 move in 起同步积累）、横向耦合（多系统集成与人员磨合须与调试同期）. 三重耦合决定 CIM 无法事后补建.
- 关键节点为 **2027 年 3 月 1 日 move in**，CIM 建设须以此为基准倒排工期.
- 26/12 厂商进场到 27/3 Batch1 投产仅约 4 个月窗口，EAP 开发必须 "手册驱动 + 模拟器预开发" 前置. 当前最紧迫三件事：锁定 Batch1 44 台清单、收齐 Batch1 手册、POC 结论定版.
- T 级调研：T=Tier 无 SEMI 强制标准，业界有两种语义（设备导入 T0-T3 与自动化联机 T0-T3）. IE 口径（T2 手动 run / T3 自动 run）与 CIM 侧常用一致，判据建议锚定 SEMI E30/E37/E40/E87/E90/E94，建议与 IE 会签.

### 论证红线与写作约定

- 不要把必要性建立在 "子平台必须协同" 之上. 四个子平台物理独立、组织独立、可单独对外服务；需求来自各平台自身客观存在的短板（化合物手动投片、集成工艺多自动化层次、测试数据量大等），协同只是放大其价值.
- 不编造未经核实的量化指标（良率 / 成本 / 百分比），定性论证为主；量化数据须以平台基线为基准或标注为行业经验参考值.
- 段落之间不得共用同一句式模板（每段同以 "其价值是/其价值在于" 收尾即视为不合格），要求长短句交错、各段收尾互异、不用破折号堆叠.
- 去 AI 味不等于口语化：正式稿件须用中性陈述（名词化结构加 "负责/承担/依据/构成/取决于"），不用反问、比喻、拟人、感叹.
- 涉及对外接口用 "协同/对接"，不用 "集成/整合".

### 设备采购侧的接口要求

- 新购设备若仍只提供 RS232，必须要求厂商升级为 HSMS，否则严重影响 EAP 性能与 FDC 采集能力.
- 仅 RS232 的旧设备可用 MOXA 等串口转以太网服务器转 HSMS，EAP 端统一按类 HSMS 处理，但须注意转换延迟与丢包风险，转换器由 IT 自行采购.
- 无任何 SECS 能力的后道老设备（只有 PLC 或物理按钮屏）按三条路径卡控：PLC 卡控、文件 / 数据库接入（设备输出 CSV/Log/DB，EAP 定时解析做 Track In/Out 与采集）、人工兜底（扫码枪扫随工单条码过站，EAP 提供手动 UI 并强制二次确认）.
- RS485/Modbus 设备同上按 PLC 或文件通道处理.

### CIM 建设原则怎么分阶段

- 第一阶段聚焦产线核心能力建设，目标是让实验流片先跑起来. 优先部署生产调度、设备自动化与实时监控三类基础系统，构建从投片到出片的基本流程管控能力；打通关键工艺设备的通信通道，建立设备状态采集与生产指令执行机制；搭建实时监控体系做基础规则校验与异常预警. 本阶段形成实验流片的最小闭环.
- 第二阶段完善管理闭环，在产线跑起来的基础上强化数据规范性与验证效率. 补充配方集中管理、统计过程分析、实验数据归档及设备运维视图，重点建立 Recipe 版本管控与变更追溯机制，确保每次流片可复现、可核查.
- 第三阶段聚焦智能化应用深化，把沉淀的数据转为知识资产.
- 系统归属：第一阶段 MES, EAP, FDC；第二阶段 RMS, SPC, DMS 与报表；第三阶段 APC 与 AI 智能分析.
- 本中心定位不同于量产 Fab：核心目标是建设完整的实验流片平台，支撑国家课题的量产验证与中心研发进程，前期对良率的要求低于量产线，稳定性的优先级让位于快速验证与数据完整.

### CIM 需求分析分几大类展开

- 六类：业务目标与价值需求、功能需求、集成接口需求、数据需求、非功能性需求、实施与服务需求.

### CIM 总体口径有哪些要素

- 生产业务五类：材料、器件、集成工艺、先进封装、测试验证.
- 中试线生产特征六项：多技术路线并行；多品种、小批量、研产并行；工艺快速迭代；跨业务子平台协同；设备自动化水平差异大；科研生产数据价值高.

- CIM 生产系统十七个：MES, EAP, RMS, RCM, SPC, FDC, APC, DMS, YMS, PMS, AMS, RPT, FMS, RTD, AMA, LIMS, QMS.

- 总体建设原则三条：一个业务对象一个权威来源、一类专业能力一个主责系统、一个系统一个明确责任组.
- 数据链七类：生产、设备、工艺、调度、质量、厂务及实验室数据.
- 分期建设原则四项：基础能力先行、专业能力补齐、自动化逐步深化、数据价值持续释放. 建设路径四条：总体蓝图统筹、核心系统先行、专业能力补齐、数据能力深化.
- 科研中试数字化能力六项：业务流程线上化、生产执行标准化、设备控制自动化、过程监控实时化、质量管理闭环化、制造数据可追溯.
- 第一阶段建设目标为 MES 管生产、EAP 控设备、FDC 监过程，构成基础生产可运行的最小闭环；后续阶段重点为工艺过程精细化、设备运维规范化、质量良率闭环化、生产调度智能化、实验室数字化与制造数据价值化.

### 为什么 "固定底座 + 单台边际" 模型不能外推

- 曾用 REF1/REF2 两点拟合出 "人日 = 114.1 + 0.3756 × 台数"，其中固定底座 114.1 人日（5.70 人月 / 28.5 万含税）与台数无关.
- 该模型经 RCM 检验被证伪：预测 264 台需 213.2 人日，实际仅 120 人日，偏差 +78%. 属两点过拟合.
- 结论：不同系统的实施强度差异极大，实施人月必须按系统类型单独锚定，不能跨系统外推.
- 另注：REF2 授权单台 4.257 万，为 REF1（1.166 万）与 RCM（1.042 万）的 3.6~4.1 倍，推断产品档位或模块范围显著不同，不能与同档参照系混用；交叉建模只在 "同为标准化部署、无定制开发" 前提下成立.

### 定制开发在合同里怎么处理

- 定制开发须单列，不计入标准实施人月. 定制单价通常高于标准实施单价，应按实际工时结算或设上限.
- 定制范围须在合同中界定交付边界，避免形成开放区间.
- 厂商标注惯例可作判据：Function List 中凡额外收费一律显式标注 "（客制化开发）"，无标注即为标准功能；括注的环境前提（如 "需要额外准备 PiRun 服务器"）隐含 "非开箱即用"，留有事后主张额外收费的空间，技术协议须写明费用与环境的归属方.

# 2.FDC

## 接入范围与分级

### 量测 / 检测设备是否上线 FDC

- 结论：**分级选择性接入**，不是全量.
- A 级必上：工艺设备（刻蚀、沉积、清洗等主制程）走全量 FDC，覆盖过程健康与设备健康.
- B 级选上：关键量测 / 检测设备（CD-SEM、膜厚、OCD、缺陷检测）仅走设备健康通道，判定结果不入 FDC.
- C 级不上：离线、手动、便携式量测，仅数据采集入 YMS.
- 接入判据三个维度：设备健康价值 × 量测可信度影响 × 厂商 trace 数据可得性.

### 为什么量测设备接入 FDC 的必要性高于量产产线

- 本中心为 die-level 集成验证平台，交付物是 "验证结论"，量测设备漂移将直接导致结论作废、需回溯重验.
- 因此价值锚点在设备健康与量测可信度，而非过程控制收益. 该论点可写入建设依据.
- 待确认：检测判定结果归 FDC 还是 SPC/YMS；一期是否覆盖检测设备；trace 采集功能是否写入设备采购 SOW.

## 采样率与数据通道

### FDC 固定频率采集的采样率（Hz）怎么定

- SECS/GEM 中周期 trace 由 S2F23 设定、S6F1 上报，字段 DSPER 单位为 **秒**. 提要求应写 "最小 DSPER"，而非直接写 Hz.
- 分档建议：基线 1 Hz；关键制程 5–10 Hz；瞬态捕获 10–50 Hz（配事件触发窗口）；超过 50 Hz 需改走 EDA/Interface A 或厂商专有高速通道.
- 三条约束：信号特征时间（取特征时间常数的 5–10 倍）、设备 trace 能力（须写入 SOW）、平台与存储成本（10 Hz 相对 1 Hz 数据量放大十倍）.
- 工程要点：按 SVID 分组设不同采样率（快变量 5–10 Hz、慢变量 1 Hz）；高采样率不等于高检出率，短时事件采用 "事件触发 + 触发前后窗口高采样" 更有效.
- 本项目建议口径（尚未确认）：基线 1 Hz；关键工艺 5 Hz；瞬态 10 Hz + 事件窗口；SECS 通道上限 10 Hz；SOW 明确 "最小 DSPER ≤ 0.2 s 且支持按 SVID 分组".

## 功能架构

### FDC 为什么划为七个功能域

- 七域为：系统与权限管理、数据采集与上下文、监控报警与响应、算法与模型管理、报表与可视化分析、流程编排与扩展、平台集成与运维.
- 划分依据：四域为主线（数据采集与上下文 → 算法与模型管理 → 监控、报警与响应 → 报表与可视化分析，对应采集、建模、判异、复盘闭环），三域为支撑（流程编排与扩展、系统与权限管理、平台集成与运维，面向全域故独立成域）.
- 七域是功能切分，不是组织条线.

### FDC 功能清单规模与配图口径

- 规模：一级功能 76 项、二级功能 163 项（合并同名多说明行后计数）.

## 数据层分库

### FDC 的 RAW/ROUTE/ADMIN 分库怎么界定

- SPEC 依据：第 134 行要求微服务化构建 FDC 核心程序，支持 RAW, ROUTE, ADMIN 数据库分离并支持异构数据库；第 135 行要求除 Oracle 外支持 PostgreSQL 与 SQLServer；第 137 行要求 Rawdata 分表 / 文件存储，按 2 天 /1 月 /6 月 /1 年分级保留，Raw Data 与统计数据分开管理.

# 3.RMS

## 术语与口径

### EC 缩略语撞车怎么处理

- `RMS SPEC` 第 3 组的 EC 指 **Equipment Constant**（设备常量）；工程变更体系中的 EC 指 **Engineering Change**. 两者毫无关系.
- 若集成需求只写 "EC 管控"，PLM 与 RMS 团队会读成两回事. **RMS 侧该模块一律全写"设备常量（EC/SV）"，工程变更写全称不简称. **

### RMS 三层架构按什么分类

- 分类维度是 **交互对象**，不是数据流向：面向人机与业务系统的归交互层，面向配方与常量管控规则的归核心功能层，面向设备通信的归数据源层.
- 三层对业务的价值：设备增减与型号更替只影响最下层接入适配，配方管控规则与审批流程不必改动；上层界面与消息通知由交互层收敛，工程师跨子平台切换面对同一套界面与流程；校验、版本管控与常量比对集中在中层，规则变更一次生效.
- RMS 不直接与机台交互，设备通道由 EAP 承担：架构图底部为设备通道层（EAP），顶部系统交互层为泛微统一门户、泛微协同办公（签核流程）、AMS、帆软报表.

## 与工程变更体系的衔接

### 中试平台 EC 工程变更体系要点

- 三类机制 Experiment(EXP)、DEV(Deviation 临时偏离)、EC(正式变更)，分流不分治.
- 8 大类 30 个受控对象（产品设计 /BOM 物料 / 工艺 / 设备 / 质量检测 / 生产执行 / 包装物流 / 系统自动化）.
- 编码为 `Change Type-一级领域-二级对象-年度-流水号`，如 EC-PR-RCP-2027-0038.
- L1–L4 风险分级：系统评分 + 红线强制升级 + 工程师复核，降级须质量与技术共同批准.
- 客户审批由 Customer Requirement, Contract, Quality Agreement、认证状态动态触发，非按产品类别一刀切.
- 流程为 ECR → ECN → Effectivity → Validation → Baseline → Close 闭环.
- 4 个关键控制点：Effectivity, Implementation Plan, Pilot 验证、Rollback Plan.
- Baseline 六层：Engineering / Product / Process / Manufacturing / Quality / As-Manufactured.

依据：`中试平台EC工程变更管理体系及流程设计V1.0.docx`（189 段 + 27 表）.

### RMS 在工程变更体系中承担什么

- 定位是 **执行方**，主责 Recipe 主版本、审核、批准、下载规则、黄金版本与回退版本.
- 禁止事项：**不得脱离 ECN/EXP 授权修改正式 Recipe**.
- 承接现状：需求表第 6 组「Recipe 变更签核」7 条 + SPEC「签核业务接口协同」组 7 项，共约 12 项.
- 七项缺口：范围只覆盖 Recipe 单一对象；无 Effectivity 承接能力；无强制 Pilot（Pilot Run 条系补入，属可选）；无 Rollback 预案机制；无 Baseline Freeze 概念；不做 WIP 切换决策（由 MES 依 ECN 执行）；审批强度低（用既有办公协同，不设 CCB）.
- 待澄清：中试平台若本期不建 PLM，"EC 主控平台" 无着落，需在立项中明确承接方；"RMS 不得脱离 ECN/EXP 授权修改正式 Recipe" 这条反向约束在现有 RMS SPEC 中无对应条目，属新增接口需求候选.

## Pilot Run

### Pilot Run 属标准功能还是客制化

- 判定结论：**属产品标准功能**，不计定制开发费用，但须澄清三个前提.
- 证据链三条：其一，厂商原始 Function List V6.0 第 55 行（3.9 条）原文含括注 "需要额外准备 PiRun 服务器"，属环境前提而非开发项；其二，厂商标注惯例可作反证，凡额外收费的一律显式标注 "（客制化开发）"（2.9 有 3 处、2.29 有 1 处），3.9 无此标注，标注缺省即标准；其三，RMS 分册把 Pilot Run 验证列为「Recipe 管理」组下独立二级功能，与查询与排序、Golden Recipe 等标准项并列，全文无 P1- 类定制编号.
- 前提一（成本真身）：PiRun 服务器是额外硬件或环境，软件能力标准，但环境由谁出资须明确. 厂内虚拟化或新增 1 台服务器量级 5~15 万（含许可副本，视厂商政策），属环境费而非开发费.
- 前提二（唯一争议点）："提供 Pilot 验证结果的确认与转正式生效路径" 不在 Function List 3.9 原文中，是后加的表述. 若仅要求在既有签核流内把 Pilot 版本转正式并留档，属标准动作组合，靠配置实现；若要求结构化 "Pilot 结果确认单 + 独立审批流 + 批量转正界面"，属轻客制化，约 0.5~1.0 人月（2.5~5 万）.
- 前提三（易误读）：Pilot 的对象是 "RMS 重要逻辑（管控规则）本身的变更"，不是 Recipe 内容变更（后者是普通版本切换，属标准）. 即 "规则灰度发布" 能力，比普通版本管理高一档，应要求厂商提供界面截图或已交付案例作验收依据.
- 建议报价口径：不标 "含定制开发"、不计人月；单列 "PiRun 环境准备" 项（谁提供、几个节点、含不含许可）；若坚持结构化转正流程则追加 0.5~1.0 人月，比照 RCM 定制项处理.
- 风险提示：括注隐含 "非开箱即用"，建议技术协议写明 "Pilot Run 机制属产品标准功能，不含定制开发费用；所需 PiRun 环境由 XX 方提供".

## 智能协同建模

### RMS 智能协同建模可以从哪些点着力

- 口径确认为方案 A：AI 辅助 Recipe 建模属 RMS 功能增强，纳入 RMS 立项范围，不单独设项、不新增系统，不改五域 17 系统版图；建议划入 RMS 核心功能层作辅助组件，不单独设层.
- 六个着力点及切入安排：
    - 规范范围的推荐（Recipe 项允许区间推荐）. 价值高但依赖 YMS/SPC 打通，存在"推荐值被误当标准值"风险，列第二阶段.
    - 比对异常的根因提示. 价值密度最高，但需积累处置结论样本，列成长期.
    - Recipe 变更影响的预判（送签时呈现涉及产品、设备与历史异常）. 列首批首选.
    - Recipe 差异的语义化解读. 与上一项同期配套.
    - 规范模板的推荐复用. 实现简单，宜待模板积累后启用.
    - 全厂 Recipe 一致性的主动巡检（自动发现"该比对谁"）. 列首批.
- 首批选变更影响预判与一致性巡检的四条理由：本质是确定性聚合，无模型精度争议，结果可人工复算；直连签核卡点，收益直接；对现有架构无侵入，仅增分析视图；与已定 SPEC"签核可视性" 衔接，属延伸非新增范围.

### 两项前置条件是什么

- 数据字段预留："每次比对的最终处置结论" 现有 SPEC 未明确要求留存，但它是全部判断类能力的数据基础，建设阶段即须要求留存，首批不启用也要先积数据.
- 边界与权责书面界定：AI 输出仅作参考意见，不构成自动生效、放行或 Hold 的依据，Recipe 生效、签核、放行权责不变，以回应质量体系审计要求.
- 边界划定：与 APC（会实际改工艺条件）、FDC（面向设备状态实时监控）、YMS/SPC（仅作数据输入）均不重叠.

## 成本与报价

### RMS 首轮估算为什么高估了 3~4 倍

- 首轮估算（800 台设备 / 1500 用户）：纳管约 560 台，一次性建设 565~1,095 万元，中枢 800~830 万元；年度维保 80~130 万元；5 年 TCO 约 1,200 万元.
- 实际报价三家为 604 / 200 / 182 万元. 高估来源三项：计价粒度错位（仍按 560 台逐台计价，而同一份手册 = 同一套驱动，A 档复用率约 50%，按设备名逐台建型高估 36%）；纳管范围取满（把量测与辅助 200 台全额计入，实际厂商通常只对下控设备报价）；服务单价偏乐观.

### 300 台口径下的合理区间

- 统一口径（6 个月实施 / 300 台接入 / 实施费打包进成品软件价）：合理区间 180~300 万元，中枢约 220 万元.

| ------ | ------------ | ----------------- | ------------------------------ |
| 厂商 C | 182          | 0.61              | 合理，偏紧                     |
| 厂商 B | 200          | 0.67              | 合理                           |
| 厂商 A | 604          | 2.01              | 超出合理带一倍以上，需核对范围 |

### 200 万口径怎么拆成实施与授权

- 按固定底座 + 边际模型拆分（300 台，推荐折算系数 0.75）：实施 8.31 人月 = 41.6 万（含税），授权 158.4 万（含税），实施占比 20.8%.
- 折算系数取 0.75 的理由：参照系含设备侧适配工作量，RMS 的设备通信与驱动由 EAP 承接应折减；但 RMS 另有参照系未单列的工作（Recipe 项规范逐项约定、比对规则配置、签核流程与办公协同对接），两相抵消后净取 0.75.
- 敏感性：若按 800 台全量口径，实施需 22.17 人月 = 117.5 万，实施占比升至 58.7%，与参照系 13.68% 的结构严重背离，**反证 200 万总价不覆盖 800 台全量接入**.
- 税口径：公式 "人月 × 5 万/人月 = X 万（含税 6%）" 中 X 即含税金额，不应再乘 1.06. 授权部分标注的含税金额同理.

### 量测设备是否纳入 RMS

- 结论：**分级纳入**，不是二元选择.
- 关键量测设备（程式直接影响验证结论判定，如膜厚、CD、成分、缺陷分析）纳入并做版本控制、审批、参数比对与审计，可视设备能力决定是否下控.
- 一般量测设备纳入，仅做版本管理与审计记录，不下控.
- 通用测试仪器（示波器、频谱仪、矢网，无程式概念）不纳入.
- 技术约束：量测程式纳管依赖设备 SECS/GEM 支持程度. V5.0 样本 138 台中 C 档 40 台无任何配方消息，需厂商补册；X 档 17 台为非 SECS 仪器.
- 报价影响：量测不纳入可将纳管基数从 560 台降至 360~420 台，总价下浮约 15%.

### "0.3 上线率" 是怎么来的

- 测算中出现的 0.3 是 **单台接入成本 0.20~0.30 万元/台**（即 2,000~3,000 元 / 台），不是比例指标.
- 实际使用的比例口径：需 RMS 纳管设备 560/800 = **70%**（工艺设备 360 台全额纳管，量测与辅助 440 台中约 200 台需程式管理）；本期计划接入 300/800 = **37.5%**.

# 4.RCM

## 选型与前置条件

### RCM 在选型与 Move In 前是否需要需求调研

- 结论：需要，且须前置. RCM 与机台物理硬件直接交互，选型与部署决策若晚于机台 Move In，会直接影响后期实施效率与系统稳定性.

- 只要配置了 EDC PLAN 即默认进站，不想进站须开 SRC.
- Pre-bonding 支持进站前提前组 bonding group，支持多次 bond.
- 支持 MES 与 EAP 之间切换 Auto 与 Manual；支持 ZERO 二次下线.
- 建模实操路径为 by product/step import, equip import, edc import 三类导入.
- demo 覆盖：PO 订单管理、WO 工单管理、领料与退料查询、Source Lot 创建与 Batch ID 唯一标识、Product Lot Start 生成 Lot ID, Sorter Job 查询、Lot 查询、未来多个站 Hold、按 EquipID 查看派货 Lot 的 WIP/Tracking/Setup.

### 鼎华的能力表现

- 主要客群为化合物半导体.
- 集成 SPC，支持 inline 与 offline 两种方式.

### 微迈瑞与朋熙的能力表现

- 支持跨工艺段、跨 Fab/Line 建批，支持多种类型载具（Boat, Magazine, Tray）.
- Die-level 层级追溯：每个 die 赋予唯一标识，建立 wafer-die map 与 pick & place 移转信息，支持正反向追溯. map 关系与实际位置是否一致，按坐标原点唯一确定位置来验证，该验证一般划归 YMS 承担.
- 支持物料形态转换（wafer 转 die）与 cross fab 流转；支持同一物料多次 wafer start 的全生命周期追溯；具备 BOM 管理.
- Flow 建模为拖拉拽方式，但无 loader.
- 缺口：未考虑 double run 场景.

### 赛美特的能力表现

- Equipment Setup Process Category 支持 DUMMY 虚拟过站.
- 支持 6/8 寸 SMIF 的 Carrier Group Setup.
- Layout 侧支持按 wafer 数量选择 PPID.

### 厂商 demo 中用户重点关注哪些能力

- 8.25 的 demo 覆盖 PMS, EAP, FDC 三个系统，用户集中提出十项关注：FDC 触发 Hold 后是否支持签核修改模型；不同腔体跑不同工艺时能否按腔体管理并设置模板；step ID 的重要性与是否可提供；是否支持 stop Chamber 与 stop Tool；单变量模型的 VIEW LIMIT 能否增加 update user；是否支持叠图；批次数据查询与 Running data 导出列表；Report 能否收集设备报警并明确多批次同时 run 时以哪个为准；模型版本管理是否支持 comment；EDA 是否支持及实际有无应用.
- 其中 EDA 一项厂商回支持，但现场无应用案例.

### FDC 与 MOCVD 场景的关注点

- FDC demo 实操用于核对 guardBand 的实际处理方式.
- MOCVD 建模以炉次号为单位创批，部分场景指定使用的机台炉；工艺为外延生长，涉及石墨盘与 MO 源.

### 快速验证批次怎么建模

- 需区分常规批次与研发批次的快速验证口径，两者在建模与判定规则上不同.
- 量测数据获取有两类方式：一类由 MES 通过插件直接读取机台输出的量测文件；另一类机台不自动输出文件，须提供固定格式文档后由系统解析.
- 该类验证的共同特征是数据点少、干扰项少.
- 触发方式须明确按时间到期触发，并涉及标片有效期管理.
- 快速批验证结果回写至同圈层，其机制与炉管 Monitor 贴值类似；remo 次数不设限.

## 非功能性需求

- 定义
    - 软件产品为满足用户业务需求而必须具有且除功能需求以外的特性.
- 影响
    - 影响着产品是否能持续稳定并高效的提供服务.
- 常见类别
    - 性能需求
        - 响应时间
            - **基本**：页面间跳转时间 ≤ 3s，精确搜索反馈结果 ≤ 1s
            - **优化**：从产品体验出发做优化，比如某个页面数据量大，导致加载时间长，给用户提供加载进度条、预计加载时间，减少用户焦虑. 以及日常使用的分页加载，每次加载部分数据，当用户进行翻页时，再逐渐加载.
        - 吞吐量
            - **定义**：单位时间内成功地传送数据的数量.
            - **关联**：与系统并发相关，根据业务量估算系统需要支持多少并发.
        - 资源利用率
            - **定义**：指企业投入服务器这类资源，所发挥的资源利用百分比.
        - 事务处理能力
            - **TPS**：(Transactions Per Second)，指的是服务器每秒能够完成的事务个数. 它衡量的单位是事务 (Transaction).
            - **QPS**：(Queries Per Second)，服务器每秒能够响应的查询请求次数，它衡量的单位是请求 (Request).
        - 数据采集频率
        - 告警处理时延
        - 并发能力
        - 可用性
        - 数据容量
    - 安全性
        - 保密性
            - 数据加密保护，保证数据在采集、传输、处理过程中不被偷窥、窃取、篡改.
        - 防泄漏
            - 通过对档案进行读写控制、打印控制、剪切板控制、拖拽、拷贝/截屏控制、内存窃取控制等技术，防止泄露档案数据.
        - 权限控制
            - 根据用户权限控制访问数据进行操作记录.
        - 防攻击
            - IP 限制，高频访问限制.
    - 可维护性与可扩展性
        - 模块性
            - 当某些业务流程变动多，此时将系统功能模块化，支持灵活配置，有利于减少重复开发量.
        - 可复用性
            - 类似组件应该统一设计，在需要用到的地方可进行微调然后调用.
        - 易分析性
            - 易诊断缺陷或失效原因. 如日志记录系统，可追踪系统的历史使用情况.
    - 可靠性
        - 易恢复性
            - 在发生故障后，重建其性能水平并恢复直接受影响数据的能力. 如发布新版本，需要做好回滚方案，以备异常紧急处理；文件误删除可进行恢复.
        - 容错性
            - 在系统出错时，不影响用户的行为操作与数据，比如：掉网，数据的录入做好本地保存，在网络恢复后，自动上传保存.
        - 成熟性
            - 系统故障率需要保持在一定的水平下.
    - 易用性
        - 易学习性
        - 易操作性
        - 用户错误防御机制
        - 用户界面美观

# AI+CIM 智能化篇

## EAP

### AI 协同运行底座

AI 能力以内网私有化部署为主，机台控制指令、生产报文与实时通讯数据不进入任何 AI 链路. 确需调用外部大模型时，由内网工作站经 VPN 专线发起，仅提交脱敏后的日志文本、结构化数据与文档内容，返回结果回传内网落库，并保留调用对象、时间与内容的记录以备追溯. AI 产出的全部内容均为建议性信息，不直接写回设备或参与流程判定.

### 设备通讯异常智能诊断

面向 EAP 与机台通讯中断、报文超时、SECS 指令无应答等异常，由 AI 关联分析事件前后的 SECSLog, StatusLog 与 ErrorLog 片段，给出可能原因的判断次序与排查路径；同类异常按设备类型归集，沉淀为可检索的诊断条目，供后续问题直接引用.

### 跑货异常处置辅助

跑货中断或触发 Hold 时，AI 比对当前 Lot、设备与 Recipe 状态同最近一次正常生产的差异，输出处置建议与恢复步骤；值班人员执行后的处置结果与耗时回写，作为后续同类判断的样本.

### 设备对接文档智能解析

新设备导入阶段，AI 读取厂商提供的 SECS/GEM 手册与设备规格文件，提取 SV, EC, CEID, ALID, RPTID 等定义及状态机行为描述，输出设备驱动配置草表与待确认事项清单，压缩人工整理的时间.

### 日志智能问答

CIM 运维人员以自然语言提出查询意图，如某设备在某时段内某类异常的发生次数与分布，由 AI 转换为检索条件在内网日志库中执行，并将命中结果整理为结论与依据清单；原始日志不出内网，仅统计结论与脱敏片段用于生成表述.

### 建议复核与知识沉淀

AI 输出的通讯异常诊断结论、跑货异常处置建议、手册解析草表，由 EAP 工程师在处置完成后回填采纳情况；未采纳的标注原因，区分结论不成立、与现行作业规范冲突、信息不足三种情形. 记录按设备 TYPE、厂商与异常类别归集，例如 S7F19 获取 PPID List 失败、S1F3 状态查询超时、Load Port E84 未完成、断线重连后的恢复处置，沉淀为可复用的诊断条目与处置步骤. 随样本积累，按各类情形的采纳率与误判分布反向修正提示内容与触发条件，新 TYPE 导入或同类异常再现时可直接调用既有条目.

## FDC

### AI 协同运行底座

FDC 采集的 Raw Trace, Summary 与 Context 数据体量庞大且含工艺细节，全部保存在内网数据库，不进入外部链路. 需要大模型能力时，内网分析节点先完成汇总与脱敏，仅提交统计特征、报警描述及必要的脱敏片段，经 VPN 专线访问模型服务，返回结果回传内网落库. AI 输出在本系统内仅为分析与建议来源，OCAP 的执行仍由既有规则引擎判定，AI 不参与连锁动作的直接触发.

### 报警根因智能归因

同一时段产生的多条报警，由 AI 结合各自关联的 Tool, Chamber, Recipe, Step 与 Context 做聚类，识别成因相同或出自同一工艺步骤的报警簇，输出根因排序与建议核查方向；归因结果与报警记录一并保存，用于后续复盘及规则优化.

### 模型健康度智能体检

对已激活的 UVA/MVA 模型，AI 按期复核规格宽度、样本分布漂移与激活状态，标记长期未报警或频繁误报的模型并给出复核建议. 该检查面向模型投入使用后的持续有效性，与建模阶段的算法选择相互独立.

### 告警规则智能推荐

以历史 OOC/OOS 记录、人工处置结论与参数分布变化为依据，AI 就 Alarm Rule 的新增、合并或阈值调整提出建议，并说明每条建议所依据的数据范围与样本数量；建议经仿真测试和人工确认后方可启用，不自动写入规则库.

### 自动限值辅助决策

批量自动生成 SPEC 时，AI 参考该腔室历史数据的分布形态、工艺变更记录与既有规格的命中情况，就 Sigma 倍数、百分比或 Delta 的取值给出候选区间，并提示样本量不足、分布异常等需要另行判断的情形，供 PE 确定训练样本组与限值方案.

### 自然语言取数与趋势判读

支持用户以自然语言描述分析意图，由 AI 调用 FDC 既有功能进行检索与绘图，并对数据趋势给出判读，涉及长期趋势的判读同时列明所依据的数据点与筛选条件，便于复核. 支持记忆并生成定时任务功能.

## RMS

### AI 协同运行底座

Recipe Body, Parameter 与设备常量属核心工艺资产，全部保存在内网，未经脱敏不得外送. 调用大模型能力时，由内网终端经 VPN 专线发起，仅提交参数名称、比对差异描述与去标识后的履历信息，返回结果回传内网落库，调用对象、时间与内容留痕备查. 比对、签核、上传下载等业务动作仍由本系统按既有规则执行，不因引入 AI 而改变判定口径.

### Recipe 差异智能解读

系统得出的 FullBody, CheckSum 或 Parameter 比对结果，由 AI 转写为可读的差异说明，区分关键参数与一般参数，指出变化方向、幅度，并提示可能影响的工艺环节；说明与比对记录关联保存，供用户与签核人参考.

### 变更影响面分析

Recipe 或设备常量（EC）版本发生变更时，AI 依据设备、机型、产品与 Recipe 之间的关联关系及历史履历，梳理受影响的设备范围、可能引用的产品与在制批次，形成影响清单提请复核，减少凭经验判断造成的遗漏.

### 程序解析辅助

对 Parse Adaptor 尚未覆盖或结构不规则的设备程序，AI 辅助识别参数段落与数据类型，就适用的比较方式（Absolute, ByRange, ByTolerance, ByList）及需要关注的关键参数给出建议，减轻新机型导入时的人工整理工作；解析结论经人工确认后方纳入模板.

### 签核要点提示

待签核的 Recipe 提交后，AI 依据历史签核记录、既有管控规则与本次变更内容，列出需要重点确认的条目以及过往同类变更曾被驳回的原因，帮助签核人快速定位审查重点；签核结论仍由签核人独立作出.

### 履历自然语言查询

支持用户以自然语言检索 Recipe, Sequence 与设备常量的变更履历和校验记录，例如查询某机型近三个月内参数规范的全部修改及其发起人，由 AI 转换为查询条件并整理返回结果，检索范围限于内网数据.

### Spec 取值辅助

新建或修订参数规范时，AI 参考同型号设备的历史参数分布、既有 Spec 的命中情况与工艺变更记录，给出区间与比较方式的候选取值及其依据，供用户定稿；建议内容不直接写入模板.
